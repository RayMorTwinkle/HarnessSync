# 首次初始化的整理流程

先运行 `sync status`。已经连接时跳过第一台判断；未连接先问“这是你第一台使用 HarnessSync 的设备吗？”。无论答案如何，gh 已登录时查 `gh repo view harness-sync-config --json name,url,visibility`（也可用 `onboard repository`）；返回 `absent` 表示默认名称的仓库不存在，用户仍可能使用了其他名字；网络或权限错误仍为 `unknown`，其他失败不等于没有仓库。已有仓库或不是第一台时，先确认仓库 URL、`sync setup --url <url>` 拉取共享库，再比较扫描结果并导入。

`onboard scan`（含 prepare 和界面扫描）启动设备本地初始化会话，7 天内暂停自动部署，不修改 `deploy.auto`。`status` / `doctor` 的 `onboarding` 返回会话 ID、开始和失效时间，`autoDeploy` 显示 `needs-review` 及“初始化进行中：确认部署预览后再写入”。成功的完整手动 `apply --plan <id>`（包括无变更计划）结束会话；失败或仅部署管理技能不会结束。放弃用 `onboard cancel <会话ID>`，源配置与替换登记保留；取消或到期后恢复原设置，后续正常触发自动部署。重复扫描以最新会话为准，不接受旧 ID 取消。无需 Agent 手动关闭再打开自动部署。

先读取提示词中的扫描 ID：`onboard show <id> --json`。扫描范围是已知用户技能目录、兼容目录与本机已绑定项目；不是全盘搜索，也不是模型有效上下文的完整列表。

## 技能整理

`origin=bundled` 表示产品附带，附 `originReason` 与 `bundledBy: {name,path}`；`inventory.summary.bundledSkills` 单独计数，也计入 `excludedSkills`。识别应用包、常见安装目录、node_modules 和链接指向的软件项目；向上查找项目不越过 HOME，最多 8 层，纯技能集合保留用户分类。默认建议不导入、不上传，说明会随产品更新；用户坚持时照常 `skills import`，并不禁止导入。

扫描的 `inventory.skills[].credentials` 和 `skills show <id>` 的 `credentials` 列出技能内疑似凭证文件的相对路径，仅按文件名识别，不展示值；`inventory.summary.credentialSkills` 按真实技能目录计数。用户选择全部配置（含密钥文件）同步到私有仓库，仓库必须保持私有。不想上传的文件可用 `hsync sync ignore <技能名>/<文件>`（由同步忽略功能提供）。不得向用户索要 token、密码或私钥，不要把凭证写进指令正文或 URL。

`onboard show` 每次按当前共享库重算 `inventory.skills[].library`（same/differs/absent）及 `inventory.summary.library` 三类计数。same 复用已有 ID 并接管原生副本；absent 普通导入。differs 先集中说明关键差异并给建议：`skills import <目录> --use-library` 用共享库版本，`--replace-library` 替换共享库，`--name <新名称>` 两份都留。Agent 合并先写到独立目录，再用 `--replace-library` 导入。替换共享库或合并之前必须得到用户明确同意，替换会同步到其他设备。

使用 `inventory.skills` 中的 `hash` 比较完整目录（普通权限规范化为 Git 可保存的 644/755，执行位参与比较）。`paths` 表示同一真实目录的多个入口，不应重复导入；`duplicates` 中的 `variants` 大于一，表示同名但内容不同。

先按 `origin` 筛选：`user` 为用户来源；`platform` 为 Claude 云端同步（`skills/synced/<uuid>/`）或插件；`system` 为 `.system` 目录或 `.codex-system-skills.marker` 标记的系统内置；`tool-managed` 为技能锁文件列出的工具托管条目（含来源 URL）。后三类默认排除，说明 `originReason` / `sourceUrl`，避免复制会被其他工具覆写的内容。损坏锁文件在 warnings 中报告，分类仍可继续；无已知托管证据不等于已验证用户所有权。

默认处理 `valid=true`、`origin=user`、`ignored=false` 的通用技能；明确属于项目的保留项目范围，已有管理条目不重复创建。相同名称和完整内容的多个副本可共用一份源配置，并逐个显式接管匹配的原生目录。包内部有链接、无效元数据或平铺文件时，先说明问题，保留原件；不要批量执行扫描到的脚本。

对同名不同内容的版本，先对比正文、脚本、资源与适用范围。不能仅按时间戳选新文件覆盖旧文件。需要用户判断时，将差异集中成少量问题。为保留不同版本可在临时目录整理不同的有效技能名称后导入，原件保持可恢复。

## 链接技能的集中选择

将所有尚未管理且未忽略的用户链接技能列为一个分组问题，给出原始 `paths` 和真实 `path`，默认全部导入副本，用户可逐项选择外部保留。不要每个技能单独询问；得到选择后再处理。

导入副本：使用原始入口 `skills import <链接入口>`，核心从真实目录复制完整包。原生部署位置需显式 `--adopt`；导入后链接仍在，`plan` 显示“以副本替换链接”，`apply` 才替换，回滚恢复原始链接文本。包内链接仍然拒绝；链接父目录仍禁止写入。一个真实目录有多个原生入口时，接管完整内容相同且范围匹配的入口；兼容目录不属于可接管目标，应保留并报告。

外部保留：`onboard ignore <绝对入口路径...>` 记录所有相应 `paths` 到设备本地，不进入 Git。后续扫描标记 `ignored`，不再询问；同名部署目标显示“外部保留”信息且不写入。取消用 `onboard ignore <路径...> --remove`。

## 源目录刷新

HarnessSync 收据管理的部署位置不是独立源目录；成功 apply 清理被接管或移除位置的本机来源及指纹。旧安装通过当前收据及已成功部署快照识别并忽略遗留记录，无需手工修 JSON。链接指向外部开发目录时保留真实来源，仍检测更新；不按目录名称猜测所有权。

导入记录原始入口和链接真实源目录，按技能 ID 保存在本机。即使原生链接已替换为副本，开发仓库的变化仍可检测。`status --json` / `doctor --json` 的 `sourceUpdates` 报告“源目录有更新”或无法读取；不会声称开发源与部署实时同步。

`skills refresh <id>` / `skills refresh --all` 用源目录完整包替换库内副本，包含资源删除、二进制内容及权限，保留范围、启停和显示名。之后仍需 `plan` / `apply`。名称改变则拒绝刷新，要求单独导入；不会自动改名或修复无效技能。旧 manifest 中的绝对 source 在下一次源修改时迁移到设备本地。

## 指令整理

`inventory.instructions` 包含主文件、覆盖文件、共享指令和规则片段。`active: false` 的覆盖关系应明确说明；不要把它视为运行时已经加载。比较文本、识别公共约定和冲突，把本机路径提取为变量，把真实的工具或项目差异保留。

先通过 `rules` 保存整理后的源指令。需要把主全局文件整体转为生成内容时，运行 `onboard stage-instructions <id> --keys <key1,key2>`。该命令只登记清单文件的完整指纹；不会立即覆盖原件。`plan` 会显示删除原内容和替换为合成结果的完整差异；源片段缺失或扫描后原件变化会阻止部署。部署前有完整快照，回滚恢复原件。

非主文件、规则片段与链接仍属于外部来源，不得借初始化名义静默删除。若它们仍可能与合成指令重复或矛盾，报告尚未解决的项。

整理技能中的本机目录时，可将路径改成顶层 `SKILL.md` 的设备变量（例如 `{{vars.FORK_DIR}}`），先用 `device set FORK_DIR /本机/目录` 保存本机值。项目技能还可使用 `{{project.name}}`、`{{project.path}}`。只替换已知变量，其他模板示例不变；脚本、参考资料和资源保持原样。共享库始终保留模板原文。缺变量时保留占位符原文照常部署，只给不阻断提醒；可补齐变量后重新部署。

用 `compose instructions --json` 核对共享、工具、设备、项目规则及变量分别贡献了什么；片段按最终文件顺序返回，标记区块外文字属于用户原生内容。`pending` 表示待部署差异，有 `error` 时先处理缺变量、共用文件规则不一致或大小限制。用 `compose skill <技能ID> --json` 查看技能文件类别与渲染后的字节统计，缺变量先补齐；凭证只用文件大小统计，不读取内容。`syncIgnored` 目前恒为假，不表示已提供同步忽略功能。

## 发布与验收

把批量整理的具体结果汇总给用户，不要求用户逐条勾选每一个无歧义文件。先生成 `plan --json`，用户确认具体结果后再执行 `apply --plan <id>`。执行 `doctor --json` 并说明剩余冲突和外部来源。

Codex 的 `.agents/skills`、Claude 的 `.claude/skills` 可能被其他工具兼容扫描。选择单一 Harness 并不一定能严格排除其他工具，部署预览会提示此边界。共享配置的默认值适用于四个工具；旧条目保留原有选择，不自动扩大作用域。

提示词和扫描快照只保存在本机初始化目录，不进入源配置 Git。用户主动粘贴给哪个 Harness，由用户决定；不要自行上传扫描资料。

## 跨设备同步（可选）

如果之后才连接已有仓库，同内容条目会自动合并，不同内容会成为冲突，用 `hsync sync conflicts` 查看 `<store>/conflicts/<entryId>/` 并处理。

第一台且没有已有同步仓库时，本机初始化完成后可介绍 `hsync sync setup --create` 或 `hsync sync setup --url <仓库URL>`。按可用命令帮助执行；这是可选末步，不把本地 Git 历史当作已完成跨设备同步。

初始化第 0 步前，先向用户展示扫描结果的 `backupDir`：这是使用 HarnessSync 前的本机基线。说明可用 `hsync backup restore` 预览恢复，执行后关闭自动部署。没有完成备份时不要继续部署；大于 500 MB 需用户明确同意后创建。

## 上传范围与凭证

默认将完整技能包（包括凭证）同步到用户私有仓库。连接前用 `sync check --url <地址>` 确认可见性和未忽略凭证；公开为失败，未知为警告，私有显示凭证文件数量。创建仓库始终为私有。不要读取或展示凭证正文。

用户不想上传时，连接前运行 `sync ignore add <技能名或技能名/相对路径>`；支持 `*`、`**`、`?`（含通配符时给参数加引号），以及 `rule:<指令编号或完整标题>`。不能单独排除 `SKILL.md`，需要时排除整个技能。`sync ignore list --json` 查看，`sync ignore remove <规则>` 取消。规则只在当前设备生效，本机内容仍保留并正常部署。不要删除规则文件来取消。

此前上传过的内容保留远端最新版本，忽略后不上传本机变化，拉取也不覆盖本机忽略文件；旧提交不会被清除。取消规则后恢复合并，可能需要解决冲突。需要显式移除远端时，在独立克隆删除对应技能文件并提交推送；整技能同时删除条目元数据和技能目录，再同步。先在保留副本的设备设好忽略规则，并协调其他设备避免重新上传。

## 管理技能自身更新

初始化准备先安全刷新库中已有的管理技能，只有缺少时才按初始化授权安装。保留用户的作用域、启停和显示名，停用的技能不会被初始化重新启用。服务启动仅刷新已有技能，不自动安装。

共享源正文中，用户主目录下的程序入口及配置根保存为 `{{device.home}}/...`，部署时渲染；初始化提示词仍保留本机绝对路径。安装器的当前版本链接确实指向正在运行的发布目录时使用稳定入口，升级后无需固化旧发布目录。

完整生成包指纹随技能元数据同步；内容与上次生成结果不同时保留手改，不做静默替换。没有旧指纹也保守保留。看到 `SELF_SKILL_UPDATE` 提醒后，先向用户解释，再在其确认替换正文和完整资源后运行 `hsync self-skill`。刷新仍产生源提交，原生写入继续使用正常计划、收据、快照和回滚。
