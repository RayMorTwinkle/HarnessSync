# 本机首次初始化 · v0.2

初始化被拆成三个阶段：扫描、引导、AI 整理。用户无需手动勾选每个普通技能和指令段落，但不同版本和语义冲突不能靠时间戳静默决定。

## 1. 扫描快照

扫描四种 Harness 的已知用户、兼容目录与已绑定项目路径，不做全盘搜索。输出真实目录、所有入口、完整资源指纹、名称和版本关系、主全局指令、覆盖文件、共享指令及规则片段。

同一真实目录的链接合并统计；内容相同的不同副本仍保留位置。完整指纹不同才判为内容变体；链接或其他问题导致无法获得完整指纹时，标为未验证，不假装内容相同或不同。断链单独报告，不中断兄弟目录扫描。

清单和交接提示词保存在 `~/.harness-sync/onboarding/<id>/`，属于本机资料，不进入源 Git。

## 2. 安装管理技能

仅安装或更新中文管理包到检测到的 Harness。此步骤复用正常部署、差异检查和快照，但计划限定管理 Skill，不顺带发布其他待部署配置，不改写原有全局指令。

引导不是迁移完成。界面只显示“管理技能已部署，等待交给 AI 整理”。

## 3. AI 整理与发布

用户复制中文提示词，交给任意已支持 Harness。提示词给出固定清单 ID、完整 CLI 路径和整理边界，要求 AI 视扫描资料为数据，不执行技能脚本。

默认推荐共享通用技能；明确属于设备或项目的保留范围。相同内容可合并来源；同名异版、原始规则矛盾等真正分歧集中询问。已有管理技能不重复导入，异常包保留并报告。

AI 先保存源配置、展示批量结果与部署差异。需要把主全局指令整体变为合成结果时，通过 `onboard stage-instructions` 登记扫描指纹。主文件此时不变；有适用源片段、指纹仍匹配后，正常部署才会进行替换并保留原件快照。可用 `onboard unstage-instructions` 取消登记。

非主规则片段、链接和未生效副本不允许借此接口静默清理。若外部来源仍可能影响上下文，应在完成报告中保留这一限制。

## 本次本机验收

- 原始四份全局指令在管理技能引导前后逐字节一致。
- 管理包包含中文正文、中文说明、中文 Codex 显示元数据与初始化指南。
- Codex 和 Claude Code 的真实只读会话成功运行管理 CLI；均返回 `healthy: true`、零待部署变更。
- 本机存在断链、无效元数据以及包内链接，扫描会如实标识；不会在引导阶段自动替用户清理这些资料。
- 全量已有技能与全局规则的语义迁移尚待用户把生成的提示词交给所选 Harness；没有把准备好引导误报为已迁移全部配置。
