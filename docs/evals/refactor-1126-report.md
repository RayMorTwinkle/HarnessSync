# 一次预览里，同一份配置读了多少遍？

48 条全局规则渲染到四个内置工具时，工作分支起点的一次部署预览调用源清单读取方法 195 次，调用设备配置读取方法 587 次。重构后两项各为 3 次。测试为每个目标独立断言了完整输出、创建动作以及预览后文件仍不存在。设备名随后改变时，再次预览采用新值，旧计划的应用请求返回 `STALE_PLAN`。[工作分支起点](artifacts/start.json) · [重构后](artifacts/refactor.json) · [断言与计数脚本](artifacts/plan-reads.mjs)

## 为什么需要三个版本

`backup1126` 指向 v0.2.2 时期的 `008894c`。本轮动手前，`refactor/1126` 已在 `2dcab47`，期间项目增加了插件、拆分条目的存储布局和后台部署等功能。历史备份用于同题回放，判断本轮改动的收益应比较后两列。重构代码位于 `6476646`。

| 每次预览的全局规则数 | 备份 008894c | 工作起点 2dcab47 | 重构 6476646 |
| ---: | ---: | ---: | ---: |
| 1 | 6 / 6 | 7 / 23 | 3 / 3 |
| 12 | 50 / 50 | 51 / 155 | 3 / 3 |
| 48 | 194 / 194 | 195 / 587 | 3 / 3 |

单元格为一次 `Engine.plan()` 中 `Store.manifest()` / `Store.device()` 的调用次数。每个版本、每个规模预热一次再采五次，同组五次计数一致。这是方法调用计数，不能换算成物理磁盘访问次数。系统缓存、操作系统调度和其他并发任务都影响耗时；JSON 保留每次墙钟采样，本报告不据此推断用户机器的响应时间。[备份记录](artifacts/backup.json) · [起点记录](artifacts/start.json) · [重构记录](artifacts/refactor.json)

## 多读发生在哪里

用户只点了一次预览。此前，规划器取出设备配置和清单后，作用域匹配仍为每条规则读取设备信息，变量渲染又重新打开设备配置和源清单。同一条规则在多个工具中出现，读取工作就随目标数量重复。在现代存储布局中，打开源清单还可能涉及多个条目文件。三版共同支持的旧格式只有一个清单文件，因此这里没有量化多文件布局的耗时。

现在，规划器把已读入的设备、完整源清单交给本次操作的渲染上下文。项目 ID 对应名称、设备变量和规则顺序在内存中准备一次。相同的工具选择列表在该操作内复用解析结果。规则筛选、指令生成和技能模板渲染共享它。组成视图使用同一套渲染函数。只部署一个技能时，项目变量仍从完整源清单取值。

上下文随调用结束释放。下一次预览与应用时的重规划会重新读入配置。修订指纹、暂存残留和来源检查仍可独立读取状态；表中的 3 次描述的是本组无技能样本的整次预览。它不代表存在跨请求缓存，也不提供跨进程文件系统快照隔离。[规划器](../../src/core/engine.ts) · [渲染实现](../../src/core/rendering.ts) · [组成视图](../../src/core/composition.ts)

## 实验可以怎样被推翻

- **输入与环境。** macOS / arm64，Node v24.15.0。三个检出共用同一组锁定依赖。脚本创建独立临时 home 和本地 Store，植入稳定顺序的 v1 全局规则，每条包含设备名和自定义变量。四个内置工具全部选中，不安装插件，无外部技能源。初始化和清理都在采样区间外。
- **正确性判据。** 对每个工具要求恰好出现一个创建动作，目标必须等于临时 home 下该工具约定的原生路径，输出必须逐字节等于脚本独立构造的预期字符串。每次采样随后记录第一个目标的实际输出 SHA-256，四个目标均已单独断言。若换了旧变量、少了一段文字或选错工具，脚本立即失败。
- **新鲜度反例。** 采样后直接更改临时设备配置，沿用原 Engine 再预览。新计划必须呈现新设备名、具有新 ID；使用先前的 ID 应用必须被拒绝，目标须保持缺失。新增集成测试还使用当前默认存储布局，经正常的 Store 写入接口改变配置，校验预览和组成视图都看到新值。[回归测试](../../tests/plan-rendering.test.ts)
- **外推边界。** 夹具未覆盖大规模二进制技能、远端 Git 等待、多个进程竞写或真实 Harness 会话。整套仓库测试另行验证文件归属、回滚、项目隔离及 API 访问控制。文件写入和会话实际加载需要不同证据。

在含三个提交的本地仓库运行下列命令。历史版本有一条测试固定匹配目录名 `HarnessSync/dist/cli.js`，最初使用其他检出名触发了这条路径断言。复跑脚本统一使用 `HarnessSync` 作为末级目录。脚本会创建独立临时检出，打印输出目录，并保留各组结果供核对。它要求本机能使用 Git 和项目支持的 Node 版本。

```sh
npm ci
bash docs/evals/artifacts/replay.sh
# 同时复跑各版本自带的完整测试和构建
FULL_CHECKS=1 bash docs/evals/artifacts/replay.sh
```
