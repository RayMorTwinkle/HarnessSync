部署流程

从一条规则，追到一次文件写入。

repo/

保存源配置

指令、完整技能包和稳定项目 ID 进入 Git。设备变量、项目目录绑定、收据和快照由本机保存。

hsync plan --json

读取现状，生成差异

规划器读取原生文件，解析作用域和变量，列出目标路径、改动、冲突和计划 ID。CLI 与本地工作台共用这套逻辑。

hsync apply --plan <ID>

在锁内重新核对

应用时复查计划，写入前保留快照。默认自动部署使用相同的校验；要逐次手动审阅，可在编辑前关闭自动部署。

工程复盘

一次预览，要读几遍同一份配置？

模板里的设备名来自本机状态。规则增加时，重复取数的次数也会累积。在同一份 48 条规则、四种内置工具的样本上，每次预览调用 Store.device() 的次数，备份版本为 194，本轮起点为 587，本次重构后为 3。每个版本重复五次，四份目标文件的预期内容均逐字节吻合。
