第一台设备：本机 MacBook Air（8 GB），2026-11-14 开始。

## 问题

| # | 发现时间 | 问题 | 影响 | 状态 |
|---|---|---|---|---|
| 1 | 初始化第 0 步 | `onboard repository` 在 gh 已登录、仓库确实不存在时报 `unknown`（“无法确认”），应区分为“未找到”。 | Agent 只能说“无法确认”，多问一句 | 待修 |
| 2 | 安装后 | 分支版本号仍显示 0.5.0 | 界面版本不准 | 发布 v0.6.0 时改 |

| 4 | 导入前 | 初始化流程要求“先预览、确认后再写入”，但 `deploy.auto` 默认开启，导入技能会立刻自动写入各工具，绕过预览。 | 初始化时预览形同虚设 | 待修：初始化期间暂停自动部署，apply 后恢复 |
| 5 | 首次部署后 | 从 OpenCode 目录导入的 7 个技能，源目录记录为 `~/.config/opencode/skills/<名>`；部署把它们挪到 `~/.agents/skills` 后原件被删除，`doctor` 报 7 条“源目录无法读取”，`skill-source-unreadable` 是阻断通知，自动部署此后一直 needs-review。重新导入同名同内容也不会更新来源记录，CLI 没有清除来源的办法。 | 严重：首次部署后自动部署失效 | 待修：HarnessSync 自己移除或接管的部署位置不应再当作源目录；apply 移除该路径时清掉对应来源 |

## 功能需求（来自试用讨论）

| # | 需求 | 说明 |
|---|---|---|
| A | 技能凭证的识别与同步选择 | 扫描时识别凭证类文件（`.env`、`*token*`、`*.pem` 等）并告诉用户。Ray 的选择：**全部上传到私有仓库，包括密钥**，不想每台重新配。所以默认照常同步，只在初始化时说明哪些文件含凭证、提醒仓库必须私有，并提供忽略（功能 B）给不想上传的人。加密作为以后的可选项，不是默认。 |
| B | 只影响上传的忽略规则 | 类似 `.gitignore`：被忽略的技能或文件照常部署到本机各工具，只是不进入同步仓库。可以整个技能忽略，也可以只忽略其中的文件，例如 `anysearch/.env`。 |
| C | 技能也能用设备变量 | 指令已支持 `{{vars.KEY}}`、`{{device.home}}`。技能目前不做模板替换。可以考虑只对 `SKILL.md` 开放变量（例如 `{{vars.FORK_DIR}}`），资源文件仍原样复制。 |
| D | 识别“产品附带”的技能 | ego-browser（随 ego lite 安装）、de-run、oc-run2 等由某个产品安装和更新，默认建议不导入、不上传，但听用户的。依据：链接指向 `/Applications` 应用包内部或某个工具的安装目录、技能锁文件、安装器标记等。写进初始化提示词和扫描分类。 |
| E | 指令与技能的组成可视化 | 在界面里看到某个工具最终收到的指令由哪些部分组成：共享、某工具专用、本机专用、本机变量。用 GitHub 语言条那样的彩色细条显示比例，点击色块定位到对应片段。 |
| F | 指令的公共部分与差异部分 | 同一份提示词按片段组合：共享片段加工具专用片段，加设备专用片段，再加变量。是 E 的数据基础。 |

## 待在真机上验证

## 本次初始化的决定

- 第一台设备，暂不连接同步，最后再决定是否创建同步仓库。
- 技能：导入 37 个。以下 9 个暂不导入，留在原处：
  - anysearch（两份）、genbox：带凭证，等功能 A、B 做好。
  - OpenCode 里的 `cto-review`、`learning-diary`、`math-adhd`：`me-*` 版本的旧名。
  - ego-browser、de-run-subagent、oc-run2-subagent：产品附带。
- 3 个无效技能跳过：`frontend-slides`、`grill-with-docs` 缺少 SKILL.md；`pro1-to-north-star` 的 name 不是 kebab-case。
- 全局指令：暂不融合。Codex `AGENTS.md` 与 `CLAUDE.md` 保持原样，等功能 E、F 做好再试。
- “本机内存 8 GB，默认同时跑 2～3 个”是这台 Mac 特有的，以后改为设备变量。
